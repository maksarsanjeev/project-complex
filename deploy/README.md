# Развёртывание

Бэкенд живёт **целиком на виртуалке**, в контейнере. На машине разработчика он
не крутится ни частью, ни целиком — локальный запуск нужен только чтобы
проверять правки за секунды.

Адрес: **http://192.168.10.94:8787**

## Что уже стоит на виртуалке

| | |
|---|---|
| Ubuntu | 24.04.4 LTS, 4 ядра, 3.8 ГБ, диск 28 ГБ |
| Docker | 29.6.2 + compose v5.3.1 |
| Выход в интернет | клиент Xray, прокси на `127.0.0.1:8888` |
| Секреты | `/opt/complex/.env`, права 600 |
| Данные | `/opt/complex/data`, том контейнера |

## Почему сеть хоста

Выход в интернет идёт через Xray, который слушает **строго на `127.0.0.1`**.
Из обычной сети контейнера этот адрес указывал бы на сам контейнер, и запросы
к модели никуда бы не ушли. Открывать Xray наружу ради этого не хочется, поэтому
контейнеру отдана сеть хоста. Отсюда же и порт в адресе: контейнер слушает
напрямую, без проброса.

## Обновление

```bash
cd /opt/complex/src
docker compose -f deploy/docker-compose.yml up -d --build
```

Сборка идёт на виртуалке: четыре ядра справляются, а тянуть образ из реестра
пока незачем — приватный репозиторий потребовал бы класть сюда токен GitHub.

## Полезное

```bash
docker compose -f deploy/docker-compose.yml logs -f      # смотреть логи
docker compose -f deploy/docker-compose.yml restart      # перезапустить
curl -s http://127.0.0.1:8787/health                     # живой ли
systemctl status xray                                     # состояние прокси
```

Проверить, что выход в интернет работает:

```bash
curl -s -o /dev/null -w '%{http_code}\n' -x http://127.0.0.1:8888 \
  https://openrouter.ai/api/v1/models     # ожидается 200
```

## Тонкость про прокси

Одного `HTTPS_PROXY` мало: встроенный в Node `fetch` его игнорирует, пока не
выставлен `NODE_USE_ENV_PROXY=1`. Замерено на живом сервере — с одной
переменной 403, с обеими 200. Обе прописаны в `.env`.
