# Архитектура

> Статус на 2026-07-26: веб-морда, gateway, хранение, живая модель и связь с
> движками работают. Помеченное `план` ещё не сделано.

## Общая схема

```
     СЕРВЕР (виртуалка, Docker)              РАБОЧАЯ МАШИНА (Windows)
┌──────────────────────────────────┐     ┌────────────────────────────────┐
│  ВЕБ-МОРДА (apps/web)            │     │  АГЕНТ (apps/agent)            │
│  вьюпорт · граф · чат · сессии   │     │  опрос движков раз в 5 с       │
└───────────────┬──────────────────┘     └───────┬────────────────────────┘
                │ Transport (WS /ws)             │ HTTP / TCP на 127.0.0.1
┌───────────────▼──────────────────┐             │
│  GATEWAY (services/gateway)      │◄────────────┘
│  сессии · переписка · SQLite     │   WS /agent, соединение ИСХОДЯЩЕЕ
│  цикл вызова инструментов        │   от рабочей машины, вход по токену
│  реестр агентов                  │             │
└───────┬──────────────────────────┘     ┌───────▼────────────────────────┐
        │ HTTPS через прокси             │  ДВИЖКИ                        │
┌───────▼──────────────────────────┐     │  SketchUp  :8080+ свой плагин  │
│  НЕЙРОСЕТИ                       │     │  Rhino     :1999  rhinomcp     │
│  OpenRouter: Sonnet 5 / Opus 5   │     │  Blender   :9876  blender-mcp  │
│  CLI: codex/gemini/claude  план  │     └────────────────────────────────┘
└──────────────────────────────────┘
        ┌──────────────────────────┐
        │  MCP: БАЗА ЗНАНИЙ  план  │
        └──────────────────────────┘
```

**Почему соединение исходящее от рабочей машины, а не наоборот.** У моста
SketchUp есть `execute_ruby`, у Rhino — выполнение C#, у Blender — Python.
Открыть их порты в сеть значит отдать любому в локальной сети выполнение
произвольного кода на машине архитектора. Поэтому мосты остаются на
`127.0.0.1`, входящих портов не появляется, а звонит агент.

## 1. Веб-морда

Vite + React + TypeScript. Никаких прямых обращений к сети из компонентов —
весь ввод-вывод идёт через `Transport` (`packages/protocol`). Сейчас подключён
`MockTransport`; замена на `WsTransport` не затрагивает UI.

Единица измерения по всему пайплайну — **миллиметр**.

## 2. Мосты движков

| Движок | Мост | Порт | Кадр |
|---|---|---|---|
| SketchUp | наш, [`engines/sketchup`](../engines/sketchup/) | 8080 и далее любой свободный | HTTP, JSON-тело |
| Rhino / Grasshopper | чужой [rhinomcp](https://github.com/jingcheng-chen/rhinomcp), MIT | 1999 | TCP: 4 байта длины + JSON |
| Blender | чужой [blender-mcp](https://github.com/ahujasid/blender-mcp), MIT | 9876 | TCP: голый JSON |

Чужие мосты **не форкаются и не хранятся в репозитории**: ставятся как обычные
плагины, агент говорит с их сокетом. Установка — [engines/rhino](../engines/rhino/README.md),
[engines/blender](../engines/blender/README.md). Свои наработки по Rhino
(проверка дисциплины, интроспекция API) перенесены поверх как доменный слой.

**Многооконность.** SketchUp — единственный, где окон бывает много сразу: у
архитекторов открыто по пять-десять моделей. Каждое окно — отдельный процесс со
своим портом; занят 8080, берётся любой свободный. Плагин пишет о себе «визитку»
в `%LOCALAPPDATA%\complex\instances\`, агент их читает. Живость определяется по
возрасту визитки, а не по PID: на Windows номера процессов переиспользуются, и
мёртвый PID отвечает «жив».

Когда открыто несколько окон, выбор окна обязателен — вызов без него падает со
списком открытых. Молча взять первое значит однажды построить стену в чужом проекте.

Мосты подключаются к gateway как MCP-серверы, а не вызываются напрямую из
браузера. Обмен геометрией между станциями — по двум рельсам: семантический
(Speckle) и прямые «жёлобы» точности (`import_3dm` Rhino→Blender, `.skp` ≤2021
для Rhino↔SketchUp, USD только для финальной визуализации).

## 3. MCP-серверы базы знаний `план`

Отдают знание как MCP-ресурсы, а не как раздутый контекст:

- **архив опыта** — по проекту на файл, фиксированная секционная структура,
  выборочная подгрузка одной секции вместо файла целиком;
- **карточки сборок** — микро-файлы «одна техника = один файл» (окно в кирпичной
  стене, дверная коробка, лестница, узел стена-плита, парапет);
- **нормы как данные** + архитектурный валидатор (потолки 2.7–3.3 м, стены
  250–510 / 100–120 мм, плиты 200–220, двери 2100×900, подоконник 850–900,
  ступени 150–180/280–300, четверть 65×75, парапет ≥1100);
- **логгер команд** — последовательности реальных команд моделлера в JSONL:
  тот самый «исходник» мастерства, который стирается в готовом файле.

## 4. Мозговой центр `план`

Серверная часть: держит сессии, очередь задач, стриминг в веб-морду, решает,
какой движок и какая модель берут задачу, и гоняет цикл
**построить → отрендерить → раскритиковать → починить**.

Подключение нейросетей — двумя способами:

- **API** — ключ пользователя, прямой вызов (Claude, GPT/Codex, Gemini,
  локальные через Ollama, плюс генерация картинок gptimage / nano banana 2);
- **CLI** — локально запущенный агент (`codex`, `gemini`, `claude`) сам
  подключается к мозговому центру и влияет на ход работы. Это не обёртка над
  API: у CLI-агента свой инструментарий и своя инициатива.

Оба режима переключаются в шапке чата (`API ⇄ CLI`).
