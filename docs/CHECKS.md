# Как проверить, что всё работает

Ручные сценарии приёмки. Каждый пункт — что нажать и **что именно должно
получиться**. Если результат отличается — это баг, а не особенность.

```bash
npm run dev
```

Открыть `http://localhost:5273`.

> **Сброс к заводскому состоянию.** Приложение теперь запоминает сессии и графы.
> Чтобы вернуться к исходным данным, выполнить в консоли браузера:
> ```js
> localStorage.removeItem('complex.mock.v1'); location.reload()
> ```
> Раскладка панелей хранится отдельно, в ключах `complex.layout` и `complex.center*`.

---

## 1. Узлы: добавление, правка, удаление

1. Вкладка **НОДЫ**. В левом верхнем углу холста — квадратная кнопка **+**.
2. Нажать её.

**Ожидается:** открывается палитра со всеми типами узлов, разбитыми по группам.
Тот же результат даёт клавиша `Tab`, а также правая кнопка по пустому месту холста —
в этом случае узел встанет ровно туда, где был щелчок.

3. Выбрать любой тип, например **Скругление**.

**Ожидается:** узел появляется на холсте с заполненными настройками
(у скругления радиус `10 мм`), а не с нулями.

4. Правая кнопка по узлу.

**Ожидается:** меню с пунктами **дублировать** и **удалить**.

5. Выделить узел и нажать `Delete` или `Backspace`.

**Ожидается:** узел исчезает вместе со всеми своими связями. Правая кнопка
по связи даёт пункт **убрать связь**.

6. Клик по узлу **Массив**, правая панель, секция **ИНСПЕКТОР**.

**Ожидается:** `УЗЕЛ Массив`, `ТИП op.array` и четыре поля — `КОПИЙ`,
`ШАГ X`, `ШАГ Y`, `ШАГ Z`, у последних трёх единица `мм`.

7. Поменять `КОПИЙ` на `60`. Можно ввести с клавиатуры, а можно **тянуть за
   серую плашку с названием** влево-вправо — это драг-скраб, `Shift` замедляет.

**Ожидается:** на карточке узла в графе сразу меняется строка `count 60`.

8. Клик по узлу **Агент**.

**Ожидается:** списки `МОДЕЛЬ` и `ПОДКЛЮЧЕНИЕ` (`api` / `cli`) и три тумблера —
`САМОПРОВЕРКА`, `ГРУППИРОВАТЬ`, `ДИСЦИПЛИНА`. Клик по тумблеру закрашивает
квадрат. Это те самые настройки генерации, которые агент спрашивает в начале задачи.

9. Клик по узлу **Промпт**.

**Ожидается:** многострочное поле с текстом промпта, а не однострочный ввод.

## 2. Состояние переживает перезагрузку

1. Выполнить пункт 1 (поставить `КОПИЙ = 60`).
2. Нажать `F5`.
3. Вкладка **НОДЫ**, клик по узлу **Массив**.

**Ожидается:** `КОПИЙ` по-прежнему `60` — и в инспекторе, и на карточке узла.

4. Дополнительно: переименовать сессию (пункт 7), перезагрузить страницу.

**Ожидается:** новое название на месте.

5. Секция **ПАРАМЕТРЫ МОДЕЛИ**, поменять `ШАГ` с `3600` на `7050`, перезагрузить.

**Ожидается:** `7050` на месте, башня перестроена под новый шаг. Состояние
замков и режим отображения тоже сохраняются.

## 3. Валидация связей по типам портов

Тип порта закодирован **формой глифа**: `●` геометрия, `▲` параметры, `■` данные.

**Отрицательная проверка.** Потянуть от правого порта узла **Агент** (`▲ план`)
к левому порту узла **База знаний** (`■ запрос`).

**Ожидается:** связь НЕ создаётся, линия не прилипает. Число связей не изменилось.

**Положительная проверка.** Потянуть от правого порта узла **Массив**
(`● геометрия`) к левому порту узла **Экспорт** (`● геометрия`).

**Ожидается:** связь создаётся.

**Ещё два запрета:** соединить узел сам с собой и повторить уже существующую
связь между теми же портами — оба случая отклоняются.

## 4. Аутлайнер, видимость и блокировка

Панель **СЦЕНА** внизу слева. Слои названы по материалу: `бетон`, `железо`, `стекло`.

1. Запомнить `ПОЛИГОНЫ` в левом верхнем углу вьюпорта.

**Ожидается:** `2 640` — и та же цифра в шапке панели СЦЕНА: `2 640 полигонов`.

2. Клик по «глазу» у строки `диагрид_несущий`.

**Ожидается:** рёбра диагрида **исчезают из вьюпорта**, строка становится
зачёркнутой и серой, `ПОЛИГОНЫ` падают `2 640 → 912`, `ОБЪЕКТОВ` `4 → 3`,
а шапка СЦЕНА показывает `912 из 2 640 полигонов`.

3. Клик по «глазу» у **слоя** `стекло`.

**Ожидается:** гаснет весь слой целиком, `912 → 624`.

4. Вернуть обе видимости.

**Ожидается:** снова `2 640` во всех трёх местах.

5. Клик по корпусу башни в 3D-сцене.

**Ожидается:** в HUD `ВЫДЕЛЕНО` появляется имя части, например `diagrid`.

6. Клик по замку у этой части в аутлайнере.

**Ожидается:** `ВЫДЕЛЕНО` сбрасывается в `—` — заблокированное не остаётся выделенным.

7. Клик по тому же месту башни ещё раз.

**Ожидается:** выделяется **другая** часть (например `glass`) — луч проходит
сквозь заблокированную. Снять замок, кликнуть снова — выделяется исходная.

8. При выставленном замке посмотреть на строку части в аутлайнере и на
   секцию **ПАРАМЕТРЫ МОДЕЛИ**.

**Ожидается:** имя части не нажимается, а поля параметров, которые меняют
заблокированную часть, погашены и не тянутся драг-скрабом; внизу секции
появляется пояснение. Замок на диагриде гасит все шесть полей — каждое из
них меняет его геометрию. Снятие замка возвращает поля в работу.

## 5. Свойства объекта

1. Клик по названию части в аутлайнере **или** по геометрии во вьюпорте.

**Ожидается** в секции ИНСПЕКТОР, например для диагрида:

| поле | значение |
|---|---|
| ИМЯ | `диагрид_несущий` |
| ТИП | `group` |
| МАТЕРИАЛ | `железо` |
| ГАБАРИТ | `22 000 × 22 000 × 86 400 мм` |
| ТРЕУГОЛЬНИКОВ | `1 728` |

2. Секция **ПАРАМЕТРЫ МОДЕЛИ**, поменять `ЭТАЖЕЙ` с `24` на `40`.

**Ожидается:** башня перестраивается на глазах, габарит и число треугольников
в инспекторе и аутлайнере пересчитываются.

## 6. Поиск по переписке

1. В поле поиска ввести `профиль`. Это слово есть только **внутри сообщения**
   сессии SES-014 и ни в одном заголовке.

**Ожидается:** в списке остаётся одна сессия — «Башня с диагридом…».

2. Ввести `rhino_io` — это имя инструментального вызова.

**Ожидается:** снова находится SES-014.

3. Ввести `абракадабра`.

**Ожидается:** «ничего не найдено».

4. Нажать крестик в правой части строки поиска.

**Ожидается:** запрос стирается одним нажатием, вернулись все сессии.
Крестик появляется только когда в поле что-то есть.

## 7. Переименование, корзина, удаление

1. Навести курсор на карточку сессии.

**Ожидается:** в правом верхнем углу карточки появляются две кнопки —
карандаш и корзина.

2. Карандаш → ввести новое название.

**Ожидается:** под строкой появляется поле правки, а справа от него —
**галочка** и **крестик**. Галочка сохраняет, крестик возвращает прежнее имя.
С клавиатуры то же делают `Enter` и `Escape`. Клик мимо ничего не сохраняет —
правка подтверждается только явно.

3. Кнопка корзины на любой сессии.

**Ожидается:** карточка исчезает из списка, внизу появляется строка
`КОРЗИНА 1`. Сессия НЕ удалена.

4. Клик по строке `КОРЗИНА`, затем по стрелке возврата.

**Ожидается:** сессия вернулась в список, корзина опустела и её строка пропала.

5. Снова удалить, раскрыть корзину, нажать `×`.

**Ожидается:** появляется кнопка `УДАЛИТЬ БЕЗВОЗВРАТНО?` — только её нажатие
удаляет по-настоящему. Второй `×` отменяет.

## 8. Что не должно было сломаться

- **Вьюпорт:** вращается на полный оборот, включая вид снизу; зум колесом
  не отскакивает в исходное положение.
- **Режимы:** `shaded → x-ray → shaded` возвращает ровно ту же картинку.
  То же для `clay`.
- **Сплиттеры:** тянутся, размеры переживают перезагрузку.
- **Тема:** переключается кнопкой в шапке, весь интерфейс меняется целиком.
- **Чат:** сообщение отправляется, ответ печатается посимвольно, блок
  инструментального вызова раскрывается по клику.
- **Консоль браузера:** ноль ошибок.

## 9. Движки: от чата до настоящей геометрии

Проверено 2026-07-26 на живом сервере. Здесь записаны и сами сценарии, и то,
что получилось, — чтобы расхождение было видно сразу, а не после раскопок.

### 9.1. Память разговора

Спросить подряд, в одной сессии:

1. «Сколько миллиметров в одном дюйме?» → **25,4**
2. «А в двух?» → **50,8**

Второй вопрос осмыслен только с историей. До появления памяти в модель уходило
единственное сообщение, и на «а в двух?» она отвечала «в двух чего?».

### 9.2. Отказ вместо выдумки

При выключенных движках попросить построить коробку. Ожидается прямой отказ и
пустой список вызовов:

> Не могу — сейчас не подключён ни один движок моделирования… Ничего не построено.

Это не воспитание подсказкой, а устройство: инструменты уходят модели **только
для запущенных движков**. Нет движка — нечего и вызывать.

### 9.3. Живое состояние движков

Запустить агента, затем SketchUp. В панели движков и в `listEngines` статус
меняется на `online` **без перезагрузки страницы** (опрос раз в 5 секунд), с
именем машины и списком открытых окон.

### 9.4. Многооконность

Открыть два окна SketchUp с разными моделями. Проверено: `test1` получил порт
60531, `test2` — 8080; запасной порт отработал, конфликта нет.

Попросить построить коробку **в конкретном окне**. Ожидается:

- вызовы уходят именно туда, куда просили;
- второе окно не тронуто — проверять **напрямую по обоим мостам**,
  а не по отчёту модели:

```bash
curl -s http://127.0.0.1:60531/model/entities | grep -i коробка   # есть
curl -s http://127.0.0.1:8080/model/entities  | grep -i коробка   # нет
```

Если окон несколько, а окно не указано, вызов обязан провалиться со списком
открытых окон. Молча взять первое — значит однажды построить стену в чужом проекте.

### 9.5. Габарит

«Построй коробку 1000×500×300 мм» → замер по bounding box даёт ровно
`X=1000.0 Y=500.0 Z=300.0`. Миллиметры в дюймы переводит мост, и только он.

Осторожно с самопроверкой в Ruby: `bounds.width` возвращает **дюймы**. Делить
их на 25.4 — ошибка направления, получится 1.6 вместо 1000. Правильно `.to_mm`.

### 9.6. Вызовы переживают перезагрузку

Открыть сессию заново: у сообщения ассистента сохранены все вызовы с их
статусами и длительностями, а поиск находит сессию по содержимому кода вызова
(`geometry/box`).
