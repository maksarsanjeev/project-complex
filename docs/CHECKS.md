# Как проверить, что всё работает

Ручные сценарии приёмки. Каждый пункт — что нажать и **что именно должно
получиться**. Если результат отличается — это баг, а не особенность.

```bash
npm run dev
```

Открыть `http://localhost:5273`.

> **Сброс к заводскому состоянию.** Приложение теперь запоминает сессии и графы.
> Чтобы вернуться к исходным данным, выполнить в консоли браузера:
> ```js
> localStorage.removeItem('complex.mock.v1'); location.reload()
> ```
> Раскладка панелей хранится отдельно, в ключах `complex.layout` и `complex.center*`.

---

## 1. Редактирование узлов

1. Вкладка **НОДЫ** в шапке центральной панели.
2. Клик по узлу **Массив**.
3. Правая панель, секция **ИНСПЕКТОР**.

**Ожидается:** `УЗЕЛ Массив`, `ТИП op.array` и четыре поля — `КОПИЙ`,
`ШАГ X`, `ШАГ Y`, `ШАГ Z`, у последних трёх единица `мм`.

4. Поменять `КОПИЙ` на `60`. Можно ввести с клавиатуры, а можно **тянуть за
   серую плашку с названием** влево-вправо — это драг-скраб, `Shift` замедляет.

**Ожидается:** на карточке узла в графе сразу меняется строка `count 60`.

5. Клик по узлу **Агент**.

**Ожидается:** списки `МОДЕЛЬ` и `ПОДКЛЮЧЕНИЕ` (`api` / `cli`) и три тумблера —
`САМОПРОВЕРКА`, `ГРУППИРОВАТЬ`, `ДИСЦИПЛИНА`. Клик по тумблеру закрашивает
квадрат. Это те самые настройки генерации, которые агент спрашивает в начале задачи.

6. Клик по узлу **Промпт**.

**Ожидается:** многострочное поле с текстом промпта, а не однострочный ввод.

---

## 2. Состояние переживает перезагрузку

1. Выполнить пункт 1 (поставить `КОПИЙ = 60`).
2. Нажать `F5`.
3. Вкладка **НОДЫ**, клик по узлу **Массив**.

**Ожидается:** `КОПИЙ` по-прежнему `60` — и в инспекторе, и на карточке узла.

4. Дополнительно: переименовать сессию (пункт 5), перезагрузить страницу.

**Ожидается:** новое название на месте.

---

## 3. Валидация связей по типам портов

Тип порта закодирован **формой глифа**: `●` геометрия, `▲` параметры, `■` данные.

**Отрицательная проверка.** Потянуть от правого порта узла **Агент** (`▲ план`)
к левому порту узла **База знаний** (`■ запрос`).

**Ожидается:** связь НЕ создаётся, линия не прилипает. Число связей не изменилось.

**Положительная проверка.** Потянуть от правого порта узла **Массив**
(`● геометрия`) к левому порту узла **Экспорт** (`● геометрия`).

**Ожидается:** связь создаётся.

**Ещё два запрета:** соединить узел сам с собой и повторить уже существующую
связь между теми же портами — оба случая отклоняются.

## 4. Аутлайнер, видимость и блокировка

Панель **СЦЕНА** внизу слева. Слои названы по материалу: `бетон`, `железо`, `стекло`.

1. Запомнить `ТРЕУГ` в левом верхнем углу вьюпорта.

**Ожидается:** `2 640` — и ровно та же цифра в шапке панели СЦЕНА.
Совпадать они обязаны только когда ничего не скрыто.

2. Клик по «глазу» у строки `диагрид_несущий`.

**Ожидается:** рёбра диагрида **исчезают из вьюпорта**, строка становится
зачёркнутой и серой, `ТРЕУГ` падает `2 640 → 912`, `ОБЪЕКТОВ` `4 → 3`.

3. Клик по «глазу» у **слоя** `стекло`.

**Ожидается:** гаснет весь слой целиком, `ТРЕУГ` `912 → 624`.

4. Вернуть обе видимости.

**Ожидается:** снова `2 640`.

5. Клик по корпусу башни в 3D-сцене.

**Ожидается:** в HUD `ВЫДЕЛЕНО` появляется имя части, например `diagrid`.

6. Клик по замку у этой части в аутлайнере.

**Ожидается:** `ВЫДЕЛЕНО` сбрасывается в `—` — заблокированное не остаётся выделенным.

7. Клик по тому же месту башни ещё раз.

**Ожидается:** выделяется **другая** часть (например `glass`) — луч проходит
сквозь заблокированную. Снять замок, кликнуть снова — выделяется исходная.

## 5. Свойства объекта

1. Клик по названию части в аутлайнере **или** по геометрии во вьюпорте.

**Ожидается** в секции ИНСПЕКТОР, например для диагрида:

| поле | значение |
|---|---|
| ИМЯ | `диагрид_несущий` |
| ТИП | `group` |
| МАТЕРИАЛ | `железо` |
| ГАБАРИТ | `22 000 × 22 000 × 86 400 мм` |
| ТРЕУГОЛЬНИКОВ | `1 728` |

2. Секция **ПАРАМЕТРЫ МОДЕЛИ**, поменять `ЭТАЖЕЙ` с `24` на `40`.

**Ожидается:** башня перестраивается на глазах, габарит и число треугольников
в инспекторе и аутлайнере пересчитываются.

## 6. Поиск по переписке

1. В поле поиска ввести `профиль`. Это слово есть только **внутри сообщения**
   сессии SES-014 и ни в одном заголовке.

**Ожидается:** в списке остаётся одна сессия — «Башня с диагридом…».

2. Ввести `rhino_io` — это имя инструментального вызова.

**Ожидается:** снова находится SES-014.

3. Ввести `абракадабра`.

**Ожидается:** «ничего не найдено».

4. Очистить поле.

**Ожидается:** вернулись все сессии.

---

## 7. Переименование, корзина, удаление

1. Навести курсор на карточку сессии.

**Ожидается:** в правом верхнем углу карточки появляются две кнопки —
карандаш и корзина.

2. Карандаш → ввести новое название → `Enter`.

**Ожидается:** название сменилось. `Escape` отменяет правку.

3. Кнопка корзины на любой сессии.

**Ожидается:** карточка исчезает из списка, внизу появляется строка
`КОРЗИНА 1`. Сессия НЕ удалена.

4. Клик по строке `КОРЗИНА`, затем по стрелке возврата.

**Ожидается:** сессия вернулась в список, корзина опустела и её строка пропала.

5. Снова удалить, раскрыть корзину, нажать `×`.

**Ожидается:** появляется кнопка `УДАЛИТЬ БЕЗВОЗВРАТНО?` — только её нажатие
удаляет по-настоящему. Второй `×` отменяет.

## 8. Что не должно было сломаться

- **Вьюпорт:** вращается на полный оборот, включая вид снизу; зум колесом
  не отскакивает в исходное положение.
- **Режимы:** `shaded → x-ray → shaded` возвращает ровно ту же картинку.
  То же для `clay`.
- **Сплиттеры:** тянутся, размеры переживают перезагрузку.
- **Тема:** переключается кнопкой в шапке, весь интерфейс меняется целиком.
- **Чат:** сообщение отправляется, ответ печатается посимвольно, блок
  инструментального вызова раскрывается по клику.
- **Консоль браузера:** ноль ошибок.
